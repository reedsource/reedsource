# 场景01 基础框架说明

## 一、定位

`scene01-template` 是**场景模块的模板工程**,本身不对应具体业务场景。它提供一份可直接复制、可独立启动、可独立打包的 SpringBoot 骨架,作为后续所有场景的起点。

它的价值不在于代码量,而在于把"每个场景是一个独立工程"这件事固化成可复制的目录结构与命名约定。

## 二、工程构成

| 文件 | 作用 |
|---|---|
| `pom.xml` | 继承 `scene` 父 pom,产出独立可执行 jar |
| `src/main/java/top/ireed/Scene01TemplateApplication.java` | 启动类,`@SpringBootApplication` 扫描 `top.ireed` 及子包 |
| `src/main/java/top/ireed/common/SceneResult.java` | 统一返回结构,`code/message/data/timestamp` |
| `src/main/java/top/ireed/controller/SceneHelloController.java` | 示例控制器,提供 `/scene/ping`、`/scene/hello` |
| `src/main/java/top/ireed/exception/SceneExceptionHandler.java` | 全局异常处理,统一异常出口 |
| `src/main/resources/application.properties` | 端口、应用名、日志配置 |
| `src/test/java/top/ireed/scene01template/Scene01TemplateApplicationTests.java` | 上下文加载测试,保证配置可装配 |

## 三、关键约定

1. **场景间零依赖**:场景之间不互相 import,公共能力下沉到 `reedjava/frame` 或 `reedtools`。
2. **包路径独立**:正式场景包路径使用 `top.ireed.sceneNNxxx`,启动类置于该包根,保证 Spring 扫描到全部 Bean。
3. **端口唯一**:从 8081 起顺延,保证多个场景可在同一台机器并行启动联调。
4. **配置外置**:`application.properties` 只放环境无关项;环境差异项使用 `application-{profile}.properties` 并在启动时指定 profile。
5. **打包方式**:`spring-boot-maven-plugin` 的 `repackage` 在父 pom 统一配置,子场景无需重复声明,产物为可直接 `java -jar` 启动的独立 jar。

## 四、验证

```powershell
# 打包
mvn -f reedjava/scene/scene01-template/pom.xml clean package

# 启动后验证
curl http://localhost:8081/scene/ping
```

预期返回:

```json
{"code":0,"message":"success","data":"scene01-template alive,17xxxxxxxxx","timestamp":17xxxxxxxxx}
```

## 五、复制本模板时必须修改的清单

- [ ] 目录名、pom 的 `artifactId` / `name` / `description`
- [ ] 启动类文件名与类名
- [ ] 包路径 `top.ireed` → `top.ireed.sceneNNxxx`
- [ ] `application.properties` 的 `server.port` 与 `spring.application.name`
- [ ] 测试类的包路径与类名
- [ ] `scene/pom.xml` 的 `<modules>` 登记
