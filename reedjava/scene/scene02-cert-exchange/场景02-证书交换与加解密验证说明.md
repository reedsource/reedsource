# 场景02 证书交换与网关加解密验证

## 一、场景定位

本场景对应方案文档《京东方与中信互通信证书加解密数据方案.md》,把文档中的**数据流程**落成可运行、可验证的工程。

场景由**两个独立 SpringBoot 工程 + 一个公共工具类模块**组成,双方可分别构建、分别启动、分别部署,也可在同一台机器同时启动联调。

| 模块 | 类型 | 端口 | 职责 |
|---|---|---|---|
| `scene02-common` | 普通 jar 库 | - | 证书生成与校验、信封加解密、证书缓存与交换流水、共享接口与定时任务、案例验证器 |
| `scene02-platform` | 可执行 jar | 8082 | 平台方(京东方):8.1.1 平台公钥证书接口 + 定时拉取资方方证书 |
| `scene02-fund` | 可执行 jar | 8083 | 资方方(中信):8.1.2 资方公钥证书接口 + 定时拉取平台方证书 |

## 二、构建与启动

```powershell
# 构建三个模块(公共模块需先 install 供两端引用)
cd reedjava/scene
mvn clean install -DskipTests

# 双端同时启动
./scene02-cert-exchange/start-all.ps1

# 或分别启动
java -Dfile.encoding=UTF-8 -jar scene02-cert-exchange/scene02-platform/target/scene02-platform-1.0.0.jar
java -Dfile.encoding=UTF-8 -jar scene02-cert-exchange/scene02-fund/target/scene02-fund-1.0.0.jar
```

启动后自检:

```
http://localhost:8082/scene02/api/admin/health   平台方
http://localhost:8083/scene02/api/admin/health   资方方
```

## 三、接口清单

### 3.1 证书接口(对应方案文档 8.1.1 / 8.1.2)

| 接口 | 提供方 | 调用方 | 说明 |
|---|---|---|---|
| `GET /scene02/api/8.1.1/platform-cert` | 平台方 8082 | 资方方 | 获取平台方公钥证书,有效期1年,轮换直接覆盖 |
| `GET /scene02/api/8.1.2/fund-cert` | 资方方 8083 | 平台方 | 获取资方方公钥证书,有效期1年,轮换直接覆盖 |

### 3.2 报文接口(网关加解密)

| 接口 | 说明 |
|---|---|
| `POST /scene02/api/message` | 双方同路径。接收对端加密信封,用本端私钥解密;失败返回 409 表示证书不一致 |

### 3.3 管理与验证接口

| 接口 | 说明 |
|---|---|
| `GET /scene02/api/admin/cert/local` | 本端证书信息(指纹、有效期、剩余天数) |
| `GET /scene02/api/admin/cert/peer` | 对端证书缓存与拉取统计(当日次数、是否需拉取、上次错误) |
| `POST /scene02/api/admin/rotate` | 轮换本端证书,直接覆盖 |
| `POST /scene02/api/admin/fault?mode=` | 故障注入 NONE / CERT_HTTP_500 / EXPIRED_CERT / EXPIRING_CERT / BAD_CHAIN_CERT |
| `POST /scene02/api/admin/cache/clear` | 清空对端证书缓存 |
| `POST /scene02/api/admin/pull?force=` | 主动拉取对端证书,force=true 绕过每日次数限制 |
| `POST /scene02/api/admin/send` | 向对端发送加密报文,请求体 `{"text":"明文"}` |
| `GET /scene02/api/admin/log` | 证书交换流水 |
| `POST /scene02/api/verify/run` | **平台方独有**:执行全部案例并返回结论 |

## 四、定时任务

双方各自运行同一个定时任务(`scene02.exchange-interval-ms`,默认 **5 分钟**,首次延迟 5 秒):

```
拉取对端证书(按每日策略) → 用对端公钥加密报文 → 发送对端 → 校验解密结果
```

对端返回 409(证书不一致)时,发送方会**强制刷新对端证书缓存并重试一次**,这是方案文档 R1 风险的自动兜底。

## 五、拉取策略与轮换(对应方案文档口径)

| 口径 | 实现 |
|---|---|
| 每次请求都判断是否拉取 | `CertCache.get(force, fetcher)` |
| 有效期内每天只在前几次真拉取 | `daily-pull-threshold=3`,超出后命中缓存 |
| 不支持新旧证书共存 | 轮换直接覆盖,旧指纹立即失效 |
| 拉到即用 | 缓存中的证书直接用于加密 |
| 校验有效期与证书链 | `CertValidator`:有效期 + 签发者匹配 + 签名校验 + JDK PKIX 路径校验 |
| 拉取失败降级 | 有效期内旧缓存兜底 + 告警流水;无缓存则失败并告警 |
| 校验不通过不降级 | 有效期/证书链不通过直接拒绝,不使用旧缓存 |

## 六、案例验证

平台方 `POST /scene02/api/verify/run` 一次跑完 13 个案例,全部通过 HTTP 调用双方真实接口完成。

| 编号 | 案例 | 方案文档位置 |
|---|---|---|
| C01 | 双方首次拉取对端证书并缓存 | §3.1 |
| C02 | 当日重复请求命中缓存不再真实拉取 | §3.1 拉取策略 |
| C03 | 平台方加密报文送达资方方并解密成功 | §3.2 |
| C04 | 资方方加密报文送达平台方并解密成功 | §3.2 |
| C05 | 证书轮换直接覆盖,无并存窗口 | §4.1 |
| C06 | 轮换后旧缓存导致解密失败,强制刷新重试恢复 | §4.2 / R1 |
| C07 | 过期证书被有效期校验拒绝 | §2 / §5 |
| C08 | 非受信链证书被证书链校验拒绝 | §2 / §5 |
| C09 | 证书接口不可用降级使用有效期内缓存 | §4.3 R5 |
| C10 | 证书临期触发更换提醒 | §4.1 |
| C11 | 无缓存且拉取失败时请求失败并告警 | §4.3 R5 |
| C12 | 双方互相校验对方证书全部通过 | §2 |
| C13 | 定时任务按周期执行证书交换 | §3.1 |

最近一次实测结果:**13/13 全部通过**(两个独立进程同时启动)。

## 七、共享信任根

平台方与资方方是两个独立进程,必须使用同一份根 CA 才能互相校验证书链。根 CA 以 PKCS12 证书库的 Base64 文本存放在公共模块资源 `scene02-trust-root.p12.base64`,由 keytool 离线生成,双方启动时从 classpath 加载为信任锚。

> 该文件仅为场景验证用的测试信任根,口令写在各自配置文件的 `scene02.trust-root-password`,**不是生产密钥**。生产环境应由 CA 机构签发并通过安全渠道分发。

## 八、编码

全部源码、配置、资源均为 UTF-8:

- Maven 编译编码由父 pom 的 `project.build.sourceEncoding=UTF-8` 统一控制
- 资源文件以 Base64/PEM 文本承载,不存在二进制编码歧义
- 运行时用 `java -Dfile.encoding=UTF-8 -jar` 启动,保证中文日志与中文报文不乱码
